# Sharded final Lean replay

The existing producer run is unchanged. Full custody success triggers source replay, then 16 shards (15 x 16 and one x 2), bounded to two concurrent compiler jobs. Each reconstructs the original pinned NF697/NF707 environment, recompiles the actual historical and F41 attachment modules, checks terminal axiom reports, and publishes only its own 2 row modules per row plus object/source provenance. All shards must share identical common compiled-object hashes and bank/input binding fingerprints. The final job re-restores the pinned common environment, verifies the entire 242-row disjoint object partition and every object hash, then invokes Lean directly on the aggregate source. It does not infer proof truth from JSON. A mismatch, unexpected dependency, missing or extra proof object, nonstandard axiom or any failed job blocks the final receipt.

The design is deliberately strict: exact compiled common-object hashes might differ across runners, in which case it stops and must be repaired using a common authenticated baseline rather than weakening checks. The 16-row shard runtime, Lean object layout, historical source replay, import memory and finite case elaboration remain runtime tests. Source preflight checks routes and five adversarial controls only; no claim of completed aggregate or independent final custody. The final producer receipt still requires an independent archive audit. Physical H/V enclosure remains conditional on original moment soundness. No F42 or RH claim.
